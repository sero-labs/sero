Architect in an existing workspace

Proposal 7, a new flow. Start an Architect project on code you already have, without making a new folder.

Same style and rules as proposals 1 to 6. The workspaces are the ones registered in the seroarchitectdev profile on 19 September. The description is an example.

1 · New project, in a workspace you have

Where will it work?Only a new folder can be chosen

New project gets a choice between a new folder and an existing workspace. An existing workspace replaces Name and Location. The project takes the workspace's name, and the rest of the dialog is unchanged.

Today: New project always creates a workspace at Location / Name. If that folder already exists and is not a workspace, Sero takes it over and rewrites its workspace file. If it is already a workspace, Sero makes a new empty folder beside it. Architect's first phase already starts from the workspace's contents, so it can plan against existing code.

Decisions

  1. Add Existing workspace to New project. Approved 2026-09-19. Screen 1.
  2. One Architect project per workspace. A workspace with a project cannot be chosen again. New work there goes to that project through "Tell Architect what to do next". Approved 2026-09-19. Screen 2.
  3. New folder only makes new folders. An existing folder is refused instead of taken over. Approved 2026-09-19. A fix.
  4. Use worktree stays off by default, as it is for a new folder. Decided 2026-09-19.
