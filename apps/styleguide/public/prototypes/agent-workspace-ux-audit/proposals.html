Agent and workspace UX — proposed changes

These are proposals, not the product. Each one answers a problem recorded in evidence.html, which holds the captured frames of the shipped build. Nothing here has been implemented, and no frame here is evidence of anything.

The visual system does not change: same surfaces, same emerald accent, same density, same controls. What changes is what is shown first, who is speaking, and how a state is named.

Rules these proposals follow

  • No truncation as a remedy. Long text is kept in full, behind a disclosure, with headings, ordered steps, labelled evidence rows or acceptance criteria. Nothing is deleted to make a card fit.
  • The user's words, not the agent's. A heading says what the project is and what it needs. The instruction an agent was given is supporting detail, and is labelled as the agent's.
  • State is a word before it is a colour. Every status carries a text label and a distinct glyph, so it survives reduced motion, a greyscale display and colour blindness.
  • No invented progress. No percentage, no ETA, no bar that implies elapsed work. Counts of finished steps are shown as counts, and freshness is shown as freshness.
  • Say nothing rather than say nothing loudly. An empty section is one quiet line, not a heading, a badge and a card.

1 · Project list — activity, owner and worker, before anything is opened

One row answers all six questions: is work happening, what is it, who is doing it, must I act, how fresh is this, and what has it cost. Owner activity and delegated activity are separate columns, so a paused Architect whose Workflow is still running reads correctly. The spend bar stays, but it is no longer the only bar on the row, so money is not mistaken for progress.

Today: one pill holds either the phase or the overlay, never both; the header promises a "needs you" column that never appears; the only bar measures spend; and "Working on M2…" reads the same whether a worker is running or nothing has happened for a week.
