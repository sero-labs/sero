Two layout decisions

Companion to proposal 2, Act on it, for issue 537. The proposal drew each screen with one set of data. Two of those screens hold facts that the drawn data does not contain, so the drawing cannot say where they go. Each question below is drawn at full size, with the same data in every option.

Nothing else is proposed here. Everything not shown on this page stays as proposal 2 draws it.

Decided

  • Spend is the figure the cost limit counts. That total includes planning and reflection, not only the runs. It is the larger of the two figures, not the smaller one the Workflow page shows today. The settings lines below read that total.
  • A paused Room's clock stops, in the engine and not only on the screen. The Room time limit counts the same wall clock the header prints, so both change together. A Room that is paused today keeps the time it has already used. The Room headers below show a stopped clock, not 229h 28m.
  • Architect saves why it stopped when a research Room ends without reporting, so the screen can name the Room and say what happened without reading its history.
  • A1 below for the settings line, and B1 below for the Room header.

The rule that settled the Room header: this work exists to remove duplication and clutter, so where an option is open, take the one that leaves less on screen and makes the decision easier.

A · The settings line when a Workflow starts from events

The drawn Workflow starts manually, so seven columns hold everything it knows. A Workflow that starts from GitHub events also carries which events start it, whether the event source is healthy, and what is queued and not yet run. There is no column for any of the three.

Today: all three are chips in the icon strip the settings line replaces, mixed in with the settings. The run count is not a gap: the activity line above the settings already says · 2 runs.

A1 · The Starts column names the events. What is running goes with the state. chosen

Settings stay seven columns. Starts names the events and opens their filters and conditions. The queue and the source belong to now, not to the settings, so they ride the activity line, in the same quiet grey. A backing-off source is not amber: nothing is asked of the user.

B · What the Room header keeps

Proposal 2 draws the Room header with the title, one state pill, the money and the clock as one quiet line, and the views. The shipped header also has a coloured status dot before the title and a turns-active count. Neither appears in the proposal's parity list, so it does not say whether they were dropped on purpose.

Today: a dot, a pill, two drawn meter bars and "2 of 3 turns active". The meter bars becoming one line of text follows the money rule and is not in question here.

B1 · Exactly as proposal 2 draws it chosen

No dot, no turns count. The pill carries the state in a word. The dot only repeats that word in colour. The count is the Team roster’s own member states added up, and the roster already names each one, so neither fact leaves the page.
