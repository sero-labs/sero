Tool call group — expanded layouts

The collapsed bar is good and stays as it is. The problem starts after the second click: Show full details swaps the tool list for a stack of cards, each card has its own header, its own border, its own scroll box, and its own padding. Four layouts below replace that stack. All four keep the same data, including live streaming input and live progress. These prototypes are interactive: click the rows, the rail, the chips.

One scroll surface

The chat scrolls. Nothing inside a tool call scrolls. Long content clamps and opens in place.

One expansion model

No summary mode and detail mode. The group opens, then each tool opens. Detail never hides the list.

No card in a card

Hairlines and indent give the structure. A border inside a border inside a border gives nothing.

Two type sizes

12px for the interface, 12px mono for content, one 10px uppercase label. Nothing else.

A write streams its input and a web search reports progress in every layout at the same time.

A · Inline rows

The smallest change. Show full details is deleted. Each tool row opens where it is, under a guide line, and shows its input pairs and its output. The list never disappears, so you keep the shape of the turn while you read one step. Live tools open themselves and stay open.

B · Rail and pane

For groups of many steps. The left rail is the list, the right pane is one detail. Only one detail exists at a time, so the height stays predictable and the eye has one place to look. The rail sticks while the pane is tall. A running tool keeps its dot alive in the rail while you read another.

C · Timeline

No boxes at all. One rail of nodes carries the sequence and the content hangs off it. Density replaces expansion: Compact gives one line per step, Full gives every input and output at once. A left colour bar marks a live band or a failure, which removes the need for a card.

D · Console

One transcript, one font. Input lines carry ›, output lines carry nothing, and the tool header sticks to the top of the group while its lines pass. The chips filter the transcript, so a group of 20 reads can be cut down to the one that failed. This is the densest option and the best one for reading a shell heavy turn.
