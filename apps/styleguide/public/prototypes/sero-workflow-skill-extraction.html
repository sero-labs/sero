Workflow → skill extraction

Static prototype for docs/features/orchestration/sero-orchestrator/specs/18-skill-extraction.md. One rule drives every screen: the pass writes a draft, and only what the user reviewed is written to the profile. A pass that finds nothing to teach is an ordinary result, not an error.

1 — The control row, after a run completed

Weekly dependency reviewcompleted

Reviews new dependency versions, opens a PR, and asks before it merges.

Skill sits with the other things you do to a Workflow, not inside the run controls. It appears only after a run completed — a skill comes from what worked.

2 — The review, which is the whole approval

Save as a skill

Every run retried the lockfile step for the same reason (from run 4, 6).
Name
dependency-bump-review
Description — what it does and when to use it
Review a dependency bump before it merges. Use when a PR only changes lockfiles or package versions, or when asked to check an update for breakage.
SKILL.md
# Dependency bump review 1. Read the diff. A bump that touches only the lockfile still needs the changelog. 2. Run `pnpm typecheck` from the repo root before anything else — a bumped type package fails here and nowhere else. 3. Run the changed package's own tests, not the full suite. 4. Report: what moved, what broke, what you fixed. **Trap:** `pnpm install --frozen-lockfile` fails after a bump until the lockfile is regenerated. Regenerate it with the repo's own tooling, never by hand.

Every field is editable, because what is saved is the user's version. The line under the title is the model's reason plus the runs it read — the provenance, in one line, with no separate panel.

5 — After saving

Edit or delete it in Admin → Skills. Extracting again defaults to updating the same skill.

The button carries the saved name the way the Library button carries its version, so the Workflow shows what it has produced without a second badge.
