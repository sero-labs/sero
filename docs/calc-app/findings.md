# Findings: Making Sero App Registration Config-Based (IMPLEMENTED)

## Current State: 5 Files Manually Edited Per New App

When adding the calculator app, we had to edit **5 files** inside `apps/desktop/`:

### 1. `vite.config.ts` — MF remotes map (build-time)
```ts
sero_calc: isDev
  ? 'http://localhost:5175/mf-manifest.json'
  : 'sero-ext://calc/mf-manifest.json',
```
**Pattern:** `sero_<id>` → dev URL with port, or `sero-ext://<id>/...` for prod.

### 2. `src/types/module-federation.d.ts` — TypeScript declaration
```ts
declare module 'sero_calc/CalcApp' {
  const CalcApp: React.ComponentType;
  export default CalcApp;
}
```
**Pattern:** 100% derivable from `id` + `component` in manifest.

### 3. `src/lib/federation-registry.ts` — lazy component binding
```ts
registry.set('calc', lazy(() => import('sero_calc/CalcApp')));
```
**Pattern:** Static `import()` keyed by `id`. Module path = `sero_<id>/<component>`.

### 4. `electron/main.ts` — two places
- `builtinPaths[]` array in `ensureBuiltinPackages()`
- `registerAppPath()` call in the dev block

**Pattern:** Both are just `path.resolve(__dirname, '../../../../packages/pi-<name>-extension')`.

### 5. `scripts/dev.sh` — four places
- Port kill list
- Start remote Vite dev server
- Wait-for-ready curl check
- Echo output lines

**Pattern:** All derivable from package path + dev port.

---

## Key Observation

Every edit follows a mechanical pattern derivable from **two sources of truth**
that already exist:

1. **`package.json` → `sero.app`** — has `id`, `name`, `component`, `ui`
2. **`vite.config.ts` → `server.port`** — has the dev port

The only piece missing from `sero.app` is the **dev port**. If we add that,
everything becomes auto-discoverable.

---

## Proposed Solution

### Manifest change: add `devPort`

```json
"sero": {
  "app": {
    "id": "calc",
    "name": "Calculator",
    "icon": "calculator",
    "stateFile": ".sero/apps/calc/state.json",
    "ui": "./dist/ui/remoteEntry.js",
    "component": "CalcApp",
    "devPort": 5175
  }
}
```

### What changes in each file

| File | Current | Proposed |
|------|---------|----------|
| `vite.config.ts` | Hardcoded remotes map | Scan `packages/pi-*/package.json` at config time, build remotes dynamically |
| `module-federation.d.ts` | Hand-written per app | Auto-generated by Vite plugin at dev/build startup |
| `federation-registry.ts` | Static `import()` per app | Use MF `loadRemote()` at runtime — no static registry needed |
| `electron/main.ts` | Hardcoded paths × 2 | Scan `packages/pi-*/` dirs dynamically |
| `scripts/dev.sh` | Hardcoded per app × 4 | Discover packages, loop over them |

### Layer-by-layer detail

**1. `vite.config.ts` — auto-discover remotes**

Replace the hardcoded remotes object with a function that scans `packages/pi-*/package.json`:

```ts
function discoverRemotes(): Record<string, string> {
  const pkgsDir = path.resolve(__dirname, '../../packages');
  const remotes: Record<string, string> = {};

  for (const dir of globSync('pi-*', { cwd: pkgsDir })) {
    const pkg = JSON.parse(readFileSync(path.join(pkgsDir, dir, 'package.json'), 'utf8'));
    const app = pkg.sero?.app;
    if (!app?.id || !app?.component || !app?.devPort) continue;

    const remoteName = `sero_${app.id.replace(/-/g, '_')}`;
    remotes[remoteName] = isDev
      ? `http://localhost:${app.devPort}/mf-manifest.json`
      : `sero-ext://${app.id}/mf-manifest.json`;
  }
  return remotes;
}
```

**2. `module-federation.d.ts` — auto-generate**

A Vite plugin that runs at `configResolved` writes the file:

```ts
function autoGenMFTypes(): Plugin {
  return {
    name: 'sero-autogen-mf-types',
    configResolved() {
      const manifests = discoverAppManifests();
      const lines = manifests.map(m => {
        const remote = `sero_${m.id.replace(/-/g, '_')}`;
        return `declare module '${remote}/${m.component}' {\n  const C: React.ComponentType;\n  export default C;\n}`;
      });
      writeFileSync('src/types/module-federation.d.ts', header + lines.join('\n\n') + '\n');
    },
  };
}
```

**3. `federation-registry.ts` — dynamic loading**

Replace static `import()` with MF's runtime `loadRemote()`:

```ts
import { loadRemote } from '@module-federation/enhanced/runtime';

export function getFederatedComponent(appId: string, component: string): LazyComponent {
  const remoteName = `sero_${appId.replace(/-/g, '_')}`;
  return lazy(() => loadRemote(`${remoteName}/${component}`) as Promise<{ default: React.ComponentType }>);
}
```

`SeroAppMount` already has the `manifest.component` field — just pass it through.

**4. `electron/main.ts` — scan packages dir**

Replace hardcoded arrays with a directory scan:

```ts
function getBuiltinPackagePaths(): string[] {
  const pkgsDir = path.resolve(__dirname, '../../../../packages');
  return readdirSync(pkgsDir)
    .filter(d => d.startsWith('pi-') && existsSync(path.join(pkgsDir, d, 'package.json')))
    .map(d => path.join(pkgsDir, d))
    .filter(p => {
      const pkg = JSON.parse(readFileSync(path.join(p, 'package.json'), 'utf8'));
      return pkg.sero?.app != null;
    });
}
```

**5. `scripts/dev.sh` — discover and loop**

```bash
PKGS_DIR="$(cd ../../packages && pwd)"
REMOTE_PIDS=()
REMOTE_PORTS=()

for pkg in "$PKGS_DIR"/pi-*/; do
  [ -f "$pkg/package.json" ] || continue
  PORT=$(node -e "const p=require('$pkg/package.json'); p.sero?.app?.devPort && console.log(p.sero.app.devPort)")
  [ -z "$PORT" ] && continue

  (cd "$pkg" && npx vite) > "/tmp/sero-remote-$(basename "$pkg").log" 2>&1 &
  REMOTE_PIDS+=($!)
  REMOTE_PORTS+=($PORT)
done

# Wait for all remotes
for i in {1..15}; do
  ALL_READY=true
  for port in "${REMOTE_PORTS[@]}"; do
    curl -s "http://localhost:$port/mf-manifest.json" > /dev/null 2>&1 || ALL_READY=false
  done
  $ALL_READY && break
  sleep 1
done
```

## Result: Zero Sero Code Changes for New Apps

After this refactor, adding a new app requires:
1. Create `packages/pi-<name>/` with `package.json` including `sero.app.devPort`
2. `pnpm install`
3. Restart dev server

No edits to any `apps/desktop/` file.

## Risks & Edge Cases

- **MF `loadRemote()` vs static `import()`**: Need to verify `loadRemote` works
  with the `@module-federation/vite` plugin in dev mode. If not, we can fall
  back to generating the static registry file alongside the types.
- **Auto-gen writes on every dev start**: The types file will have unstable
  ordering. We can sort by `id` for determinism. Should be `.gitignore`-able
  since it's generated.
- **Port conflicts**: Two packages could declare the same `devPort`. The
  discovery scan should validate uniqueness and fail-fast.
- **Production builds**: In production, remotes are loaded via `sero-ext://`
  protocol, which already uses `discoverApps()` + `registerAllExtAssets()`.
  The only build-time concern is that MF needs the remote names to exist
  in the config. The dynamic scan handles this.
