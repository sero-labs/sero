Graphify spend controls

Static prototype for the plan in docs/plans/graphify-spend-guardrails.md. One rule drives every screen: money is spent only by an explicit user action, with the model, the size and the estimated cost on screen first. A restart never spends.

This is an estimate. The real cost depends on how the model chunks the workspace.

Bytes appear next to the file count because graphify chunks by tokens: twenty dense markdown files can cost more than two thousand small source files. A model Sero has no price for reads “cost unknown for gpt-5.6-luna” and always asks, since an unknown price cannot be checked against a cap. An unanswered dialog is a no.

not built and error both wait for a person. The old code restarted a full build for any workspace with no lastBuiltAt — which every failed build has — so a failure was paid for again at every launch. The indexed card leads with money, and names the model and library version that produced the graph, so an old build stays explainable.

5 — A library upgrade is an offer, never an action

graphify 0.9.48 is available. Updating makes the next build of each workspace pay full price again, so nothing is re-indexed until you ask.

A new extractor version invalidates the cached extractions, so an automatic upgrade would spend money on its own. The dialog says so before it installs anything, and no workspace is rebuilt afterwards until the user asks for it.
