Git app — real lane graph

A lane graph that actually encodes topology can't live in a 34px gutter, so the layout changes: the graph gets the full width of the main area with its own columns, and the working tree and diff sit beneath it in a resizable split. This is the GitKraken/Fork shape, and it's close to what the Git app already does — the difference is that the two halves are balanced instead of the graph having five rows and the staging area being a strip.

The graph, drawn from real topology

Four lanes, one colour per lane, carried through to the branch rail so a branch and its lane are the same colour everywhere. Forks curve out, merges curve in, and a merge commit sits on the lane it merged into. Lane 3 has no merge curve because fix/review-and-handle-… is unmerged — which you can read off the graph without checking anything.

Dragging the split

The divider between the graph and the working tree is draggable, and the graph header collapses it outright — so the same window serves both jobs. Reading history: pull it down. Committing: push it up and the diff takes the height. You don't have to choose a layout; you choose it per moment. Below is the same app with the graph dragged to five rows.

Dragged position persists per workspace, so a repo you mostly commit in stays collapsed and a repo you mostly read stays open.

What the graph now tells you that a gutter can't. That main absorbed two branches and in which order. That fix/review-… was never merged — its lane simply stops. That feat/create-concise-… ran for three commits before merging. Lane colour is shared with the branch rail, so picking a branch on the left tells you which line to follow. Merge commits are muted in the message column, because they carry no content of their own.

What it costs. The graph needs ~390px of width for four lanes plus the branch/tag column, so the working tree and diff move below it rather than beside it. The split is draggable; collapsing the graph entirely gives you back the three-column layout from the previous prototype.
