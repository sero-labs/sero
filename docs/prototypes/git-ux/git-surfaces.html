1 · Explorer panel — eight changed files, beside a diff

The panel is fixed-height, so the two lists have to share it. Changes takes what it needs up to half the panel, then scrolls; History takes the remainder and scrolls too. Changes never gets pushed out of view by a long history, and history never disappears because you touched a lot of files. Both section headers stay put while their list scrolls.

2 · Header popover — one file, many files, drafting

The commit box stays. The sparkle in the message field drafts a message from the staged diff — the same runAdhocAgent path that already powers "Draft with AI" on pull requests. When the list is long it scrolls at five rows, so the popover height never changes and the commit button never moves. If you need to commit only some of them, that's what Open Git is for.

3 · One thing that doesn't exist yet

Commit-message drafting has no backend. Pull requests get theirs from prGenerateDraft (apps/desktop/electron/ipc/integrations/vcs.ts:192), which calls runAdhocAgent with a PR prompt. The commit equivalent is a sibling channel with a commit-message prompt and the staged diff — same seam, new prompt. Small, but it is net-new work rather than a move.
