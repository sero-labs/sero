Drawn from the code as it stands, not from the ticket. Three things to react to: what opening a diff does to your open files today, what a diff looks like as a real tab, and whether the Git app keeps its own diff pane or throws you out to the editor.

Same tab strip, diffs sitting as peers beside files. Two open at once — one working-tree changeset, one past commit — so you can compare what you're about to commit against what you shipped last week. Diff tabs are tinted violet and carry the revision, because "README.md" alone wouldn't tell you which of the two you're looking at.

4 · One file, in a viewer built for changesets

The viewer is keyed on a revision pair, not a file — so "show me just README.md" is really "show me this changeset, scrolled to README.md". The existing code already handles it: the 220px file list only appears when there is more than one file (DiffTab.tsx:98), so a single-file diff is just the diff, full width.

The one thing that has no answer yet

Click README.md in the panel twice — once from Changes, once from a past commit — and you get two tabs, because they're different revision pairs. Click it twice from the same place and you should get one.

So a diff tab's identity is the revision pair, and the file is only where it scrolls to. That is different from file tabs, where the path is the identity. Worth stating in the spec, because it decides what happens on the second click.
