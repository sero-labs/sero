The Request Pipeline
Agent (Pi SDK) agent process
The AI agent decides to interact with the UI. It calls the single sero-cli tool — the same tool used for every Sero command. No dedicated tool schema means zero additional tokens in the system prompt.
// Agent's tool call — this is all the agent sees sero-cli({ command: "app screenshot --app todo" })
tool call → executeCliBatch()
CLI Registry & Router electron main
tool.ts tokenizes the command string, resolves it through CliRegistry, and dispatches to the app command handler. Multi-line batching, rate limiting, and timeouts are handled at this layer.

executeJavaScript() / capturePage()
Cross-Process Bridge main ↔ renderer
The critical boundary. CLI commands in the main process reach the renderer via webContents.executeJavaScript() calling methods on window.__appControl. Screenshots use Electron's native webContents.capturePage() with a precise clip rect from the app panel.
Main Process → Renderer
// app-control.ts (main) const rect = await exec<AppPanelRect>( 'window.__appControl?.getAppRect()' ); const image = await win.webContents.capturePage({ x: rect.x, y: rect.y, width: rect.width, height: rect.height });
Renderer Bridge
// app-control-bridge.ts (renderer) window.__appControl = { getAppRect() { const el = querySelector( '[data-app-panel]' ); return el.getBoundingClientRect(); }, // + 10 more methods... };
Zustand store / DOM operations
Renderer — Zustand & DOM Engine renderer
Navigation commands (openApp, getList) read and write the Zustand useAppStore. Interaction commands (click, type, scroll) operate directly on the DOM within the [data-app-panel] container — dispatching real browser events.
Zustand Store
useAppStore.getState().apps for listing, setActiveApp(id) for navigation. Agent sees the same app list as the sidebar.
DOM Interaction
querySelector() scoped to [data-app-panel], .click(), .focus(), value setter via prototype descriptor, dispatchEvent().
base64 PNG ← capturePage()
Response — Image Content Transform electron main
parseOutputContent() in tool.ts detects JSON output with { type: 'image', base64: '...' } and converts it to Pi SDK ImageContent blocks. The agent sees the screenshot as a real image in the conversation — not raw base64 text.
// CLI command returns: { type: 'image', format: 'png', base64: 'iVBOR...', description: 'Screenshot of todo' }
// parseOutputContent() transforms to: [ { type: 'text', text: 'Screenshot of todo' }, { type: 'image', data: 'iVBOR...', mimeType: 'image/png' } ]

Key Design Decisions
Why executeJavaScript() instead of IPC?
The main process needs to call functions on the renderer (get rect, interact with DOM) and get return values. contextBridge only exposes renderer→main direction. executeJavaScript() lets us call window.__appControl methods and await results directly — simpler than IPC roundtrips with invoke/handle pairs for each method.
Why capturePage() not html2canvas?
Electron's native webContents.capturePage(rect) captures pixels at the compositor level — it sees everything including iframes, canvases, and WebGL. Zero dependencies. The clip rect comes from [data-app-panel].getBoundingClientRect() so only the app area is captured, not the sidebar or chat panel.
Why auto-screenshot after interactions?
When the agent clicks a button or types text, it needs to see the result. Every interaction (click, type, scroll, hover, select) automatically captures a screenshot after a 200ms settle delay and returns it as an ImageContent block. The agent gets visual confirmation without a separate screenshot command.
AD-020 Compliance — All 11 subcommands are routed through the existing sero-cli tool. The agent's tool schema payload stays identical. Zero additional tokens in the system prompt. This is the same pattern used by every other Sero extension (todo, cron, kanban, etc).
Bonus: Image Preview in Editor
ImagePreview Component
When the agent saves a screenshot to disk and the user opens it in the CodingWorkspace editor, it used to render as garbled binary text in Monaco. Now, isImageFile() detects image extensions and swaps in an <ImagePreview> component that loads the file as base64 via a new readBinaryFile IPC channel.
Detection
isImageFile() checks extension against 11 formats: png, jpg, gif, webp, svg, bmp, ico, avif, tiff…
Binary IPC
readBinaryFile() reads via fs.readFile on host or base64 < in containers. Returns base64 string.
Preview
Centered <img> with checkerboard transparency background, metadata bar showing dimensions and file size.
