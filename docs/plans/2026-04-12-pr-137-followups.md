# PR 137 Follow-ups — Small Ad-Hoc Tasklist

This is a short implementation-oriented backlog for the next pass after PR 137.
The PR substantially improved desktop preload organization, profile/type
contracts, and session orchestration, but there are still a few opportunities
to make the new behavior more systemic and less fragile.

## Goal

Turn the current local fixes into clearer subsystem invariants:

- model-availability changes should propagate consistently across all live
  desktop agent surfaces
- collaboration runtime state should not rely on fake chat messages
- agent/session state should be easier to reason about and less likely to
  regress during future refactors
- file-list caching and bridge-module changes should have stronger regression
  coverage

## Working assumptions

- Keep source files under the 500 LOC cap.
- Prefer small, well-named modules over another round of “helper pileup” in
  existing large files.
- Do not re-introduce duplicate contracts between renderer/main/preload.
- Treat the main-process model registry + settings as the source of truth; live
  sessions should reconcile to that source rather than invent their own policy.
- Prefer focused regression tests over broad snapshots.

## Task 1 — Centralize model-availability refresh propagation

**Priority:** High

### Why

PR 137 improved shared model refresh behavior, but the logic is still split
across several places:

- auth handlers refresh the registry
- shared infra recomputes one cached default model
- live chat sessions self-heal via session-specific code paths
- app-agent sessions now reconcile only on reuse
- local-model configuration refreshes the registry separately

That works, but it leaves too much room for drift. A stronger design would make
“model availability changed” an explicit subsystem event/operation with one
place to reason about what gets refreshed and why.

### Scope

Define and use one central reconciliation flow that:

1. reloads auth/model registry state
2. recomputes the shared default model
3. revalidates/reconciles all live chat sessions
4. revalidates/reconciles all live app-agent sessions
5. emits any renderer-facing updates required by the existing UI

This does **not** require a new event bus if a focused helper/service is enough.
The important part is making the behavior coherent and discoverable.

### Likely files

- `apps/desktop/electron/shared/infra/shared-infra.ts`
- `apps/desktop/electron/ipc/platform/auth/auth.ts`
- `apps/desktop/electron/ipc/agent/core/agent-model-context.ts`
- `apps/desktop/electron/ipc/agent/handlers/app-agent.ts`
- `apps/desktop/electron/ipc/agent/handlers/local-models.ts`
- desktop agent/app-agent tests under `apps/desktop/electron/__tests__/`

### Implementation notes

A good target is an explicit helper with a name like “refresh model
availability” or “reconcile live model state” that can be called from auth and
local-model flows. Reading the call site should make it obvious that both the
cached default model and all live sessions are being brought back into sync.

### Acceptance criteria

- There is one obvious path for handling auth/model availability changes.
- Open chat sessions and open app-agent sessions converge on valid models
  without depending on incidental future reuse.
- Auth-change and local-model-change regressions are covered by tests.

## Task 2 — Stop representing collaboration pending state as synthetic chat messages

**Priority:** High

### Why

The recent regression came from projecting `pendingUserQuery` into chat history
as a fake `user` message. That means collaboration runtime state and chat
history are partially coupled, which creates brittle dedupe logic and makes
rehydration more error-prone.

### Scope

Refactor collaboration pending-state rendering so that:

- the pending collaboration query lives in collaboration state only
- the UI renders that pending query as collaboration UI state, not as an
  appended chat message
- the agent store no longer needs placeholder message IDs or placeholder-dedupe
  logic for collaboration hydration

This should preserve existing UX:

- the user still sees the pending collaboration query while the run is active
- collaboration results still hydrate correctly after reload/refocus

### Likely files

- `apps/desktop/src/stores/agent.ts`
- `apps/desktop/src/stores/agent-collaboration.ts`
- `apps/desktop/src/types/collaboration.ts`
- `apps/desktop/src/components/layout/*` collaboration/chat surfaces
- `apps/desktop/electron/ipc/collaboration/runtime-state.ts`
- related renderer tests under `apps/desktop/src/**/__tests__` or nearby `*.test.tsx`

### Implementation notes

A good smell test: after the refactor, a developer reading chat-message state
should see only real chat messages. Collaboration progress should be readable
from collaboration state, not inferred from synthetic user messages.

### Acceptance criteria

- No synthetic `collab-pending-*` chat messages are needed for rendering.
- Collaboration rehydration is idempotent across repeated session syncs.
- Existing collaboration UX remains intact.
- Regression tests cover reload/refocus and post-response states.

## Task 3 — Split desktop agent store responsibilities one more level

**Priority:** Medium

### Why

`src/stores/agent.ts` is much healthier than before, but it is still close to
becoming a “knows too much” file again. Prompt sending, focus management,
collaboration state, model state, and event subscription all still meet in one
place.

### Scope

Do another small decomposition pass, with the goal of leaving `agent.ts`
primarily as store wiring plus imports from focused helpers/modules.

Good candidates to extract:

- collaboration hydration helpers
- prompt-send / optimistic-message helpers that are still store-specific
- model-state actions or action groups
- event-listener setup helpers if they can be split without hiding control flow

### Likely files

- `apps/desktop/src/stores/agent.ts`
- `apps/desktop/src/stores/agent-utils.ts`
- new helper modules under `apps/desktop/src/stores/`
- related tests under `apps/desktop/src/stores/*.test.ts`

### Implementation notes

Do **not** split purely for line count. The target is cleaner ownership and
lower cross-concern coupling. The easiest way to fail this task would be to move
large chunks into vaguely named helper files that are no easier to understand.

### Acceptance criteria

- `agent.ts` is materially smaller and easier to scan.
- Collaboration-specific logic is isolated from unrelated prompt/focus logic.
- New modules have concrete, narrow names.
- Tests still read naturally after the extraction.

- reused app-agent sessions after auth/model changes

We have some focused coverage now, but the next pass should harden the actual
seams rather than only the tiny helpers.

### Scope

  app-agent session

  (agent events, VCS events, terminal/filetree or another representative pair)

- `apps/desktop/electron/preload/api.ts`
- `apps/desktop/electron/preload/api/core.ts`

### Acceptance criteria

- At least one test would fail if a future refactor accidentally reintroduces
  repeated active-session rehydration.
- Preload bridge tests verify unsubscribe correctness for at least one evented
  bridge from each split module group.

## Task 5 — Make workspace file-list invalidation event-driven

**Priority:** Medium

### Why

The `useWorkspaceFiles` cache is better now, but it is still mostly time-based.
That means the UI can remain stale for up to the TTL after fast file changes,
which is especially noticeable in file mention/autocomplete flows.

### Scope

Refactor cache invalidation so that filetree events become the primary source of
truth.

Expected behavior:

- create/rename/delete/filetree-change events invalidate the relevant cached
  workspace entry immediately
- TTL remains as a fallback for cold caches or missed events
- manual refresh still works as before

### Likely files

- `apps/desktop/src/hooks/useWorkspaceFiles.ts`
- `apps/desktop/src/components/apps/explorer/useWorkspaceFileWatch.ts`
- `apps/desktop/electron/preload/api/workbench.ts`
- filetree-related tests in `apps/desktop/src/components/apps/explorer/*`
  and/or new hook tests

### Implementation notes

Prefer simple invalidation over trying to maintain a perfectly incremental file
index in the renderer. The goal is “fresh enough and obviously correct,” not a
complex client-side filesystem mirror.

### Acceptance criteria

- File-list suggestions stop serving stale entries after relevant file changes.
- Cache invalidation is driven by workspace-specific filetree events.
- Tests cover create/rename/delete invalidation paths.

## Task 6 — Move app-agent model-sync logic out of the IPC handler module

**Priority:** Low

### Why

The new reused-session model-sync fix is good, but the behavior currently lives
inside the IPC handler module. That is acceptable for the patch, but the policy
itself belongs in a smaller, reusable core/helper module.

### Scope

Extract app-agent model reconciliation into a dedicated module so that:

- the IPC handler remains mostly request wiring + session orchestration
- the model-sync behavior is unit-testable without handler-level imports
- future reuse/reconciliation logic can grow in one focused place

### Likely files

- `apps/desktop/electron/ipc/agent/handlers/app-agent.ts`
- new module under `apps/desktop/electron/ipc/agent/core/` or another focused
  desktop main-process location
- `apps/desktop/electron/__tests__/ipc/*` or nearby unit tests for the new module

### Acceptance criteria

- Handler file loses model policy details.
- Extracted helper/module has a narrow, descriptive name.
- Existing regression coverage moves with the extraction cleanly.
