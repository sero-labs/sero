How it works

One chrome, three platforms

The header is fully custom-drawn, so it looks the same everywhere. Only the window-control corner differs: macOS keeps its native traffic lights, Windows uses the native title-bar overlay (min/max/close + snap layouts), and on Linux Sero draws its own buttons in the same style as the rest of the bar.

The hardcoded 78 px macOS spacer goes away — the reserved area comes from the platform at runtime.

Zoom that never breaks the frame

Sero gets real zoom (⌘+ ⌘− ⌘0, persisted per profile). Only the app content scales — the chrome is sized in counter-scaled units, so it always renders at exactly 40 / 24 physical pixels.

That keeps the native traffic lights and Windows overlay buttons perfectly aligned at every zoom level, and zooming never shrinks your workspace.

Back / Next navigation

Every app (and later, views inside apps) is a history entry. Go back and forward like a browser — buttons, ⌘[ / ⌘], or side mouse buttons. History is per-window and capped at 50 entries.

Shortcuts in the chrome

Star any view to pin it as an icon in the header — a one-click jump that works even with the sidebar collapsed. Shortcuts are separate from sidebar favourites, persist per profile, and show up in ⌘K too. Overflow past 8 collapses into a menu.

Thin by design

Header 40 px + footer 24 px = 64 px — exactly today's budget. New functionality lives in existing dead space (the flexible drag area), not in extra rows. And because the chrome is zoom-invariant, that budget holds at 200% zoom.
